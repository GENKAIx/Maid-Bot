## Одна функция отправки

Всё, что горничная пишет первой, идёт через `Send`:

```flow
Telegram | сообщение в чат с ботом, кнопки — inline
Push | во все подписки браузеров (`server/src/push.ts`), кнопки — действия push
Уведомления | строка в `notices` — её читают виджет на ПК и сайт
```

Кнопки push (`/api/push/act`) делают то же, что кнопки в Telegram: отметить привычку, отложить напоминание.
Отложенный вопрос про привычку («⏰ Через 30 мин») перед отправкой сверяется с отметками (`habitAnswered()` в `scheduler.ts`):
привычку за это время отметили (виджет, сайт, чат — «да» или «нет») или удалили — напоминание отменяется, а не приходит.

**Вид письма** (`NOTICE_KINDS` в `server/src/notices.ts`). Отправитель называет вид пятым аргументом `Send`, он ложится в `notices.kind` — по нему письма отбираются в «Истории» на сайте:

| Вид | Что это | Кто ставит |
|---|---|---|
| `morning` | утренний список | `scheduler.ts` |
| `tomorrow` | «что завтра» | `scheduler.ts` |
| `evening` | вечерний итог | `scheduler.ts` |
| `plan` | напоминание о плане (и отложенное без кнопок привычки) | `scheduler.ts`, `reminderKind()` |
| `habit` | вопрос про привычку (и отложенный) | `scheduler.ts`, `reminderKind()` |
| `date` | важная дата | `scheduler.ts` |
| `game` | замечание про игры | `activity.ts` |
| `note` | наблюдения: сбежавшие задачи, найденная закономерность | `scheduler.ts` |
| `other` | без вида: «так и не смогла разобрать…» и всё, что отправлено без пятого аргумента | — |

Сервер хранит последнюю тысячу писем на человека (`NOTICES_KEEP`, раньше 200). У писем, записанных до 17.11.2026, вида нет — он угадывается по кнопкам и началу текста (`oldKind()`); новым письмам это не нужно. **Новое уведомление** — сразу со своим видом, иначе попадёт в «Прочее».

## Команды бота

**Платный доступ (24.11.2026, `access.ts`, `billing.ts`).** Платежи Telegram Stars обрабатываются **до** фильтра незнакомцев: `pre_checkout_query` приходит без чата, а `successful_payment` — из чата, который ещё может быть не привязан (оплатили по ссылке с сайта; оплата чат к записи не привязывает — только `tg_user_id`, иначе чужой, оплативший пересланную ссылку, стал бы «своим» для записи). Без пробы и подписки бот отвечает на сообщения отказом «Пробная неделя закончилась — я сохранила всё, что было…» с кнопкой «Оформить ⭐150» (ссылка `createInvoiceLink`), текст записывает заметкой; голосовое не распознаёт. Просмотр (`/today`, `/tasks`…), кнопки, отметки и напоминания — бесплатно. В `allowed_updates` (`widget.ts` `WIDGET_UPDATES`) добавлен `pre_checkout_query` — без него каждая оплата срывается по таймауту 10 с. Лимиты в штуках (с 24.11.2026, этап 2 тарифов, глава 01): сообщение, фото, `/ask`, «Повторить» и `/summary` — по одному запросу к ИИ; голосовое — запрос и секунды по `voice.duration` от Telegram, до распознавания (не распозналось — взятое возвращается; Telegram прислал то же голосовое ещё раз — без второго списания и распознавания: `pipeline.delivered` / `inFlight`); модель не ответила — запрос возвращается; упёрлись — ответ текстом из тарифов (`limitText` / `paidLimitText`), сообщение — заметкой.

| Команда | Что делает |
|---|---|
| `/start` | знакомство и строка о доступе («Пробный доступ: осталось N дн.», «Подписка до …», «бесплатно навсегда»). Незнакомец в личке (с 24.11.2026): `/start` — своя запись с пробой на 7 дней (`invite.ts` `signUp`: логин из @username, случайный пароль, адрес сервера, установщик); `/start <код>` — подарок по приглашению; код не подошёл — обычная проба. Выключатель регистрации — тариф `signupsOpen` (`/signups off` владельца или админка → «Общие потолки»; `SIGNUPS_OPEN=0` в `.env` закрывает поверх тарифа) («Регистрация сейчас закрыта»), не больше 30 новых в час и 150 в сутки на сервер (тарифы `signupsPerHour` / `signupsPerDay`) («попробуйте через час»; упёрлись — владельцу сразу, раз в час, с подсказкой `/signups off`). Незнакомцу без `/start` — «нажмите /start», записи не создаётся |
| `/today` | что сегодня |
| `/plans` | планы |
| `/tasks` | задачи |
| `/dates` | важные даты |
| `/memory` | что она помнит |
| `/habits` | привычки |
| `/summary` | итог дня сейчас (со словами горничной — через проверку частоты и потолков, `AiGate.check`; это обращение — один запрос к ИИ в лимите в штуках) |
| `/list` | виджет-список прямо в Telegram |
| `/undo` | отменить последнее |
| `/ask` | вопрос или разговор без записи |
| `/persona` | сменить характер |
| `/token` | новый ключ для виджета на айфоне (Scriptable, `iphone/README.md`); программа на ПК входит логином и паролем — до 19.11.2026 подсказка звала его «ключом для приложения на ПК» |
| `/chatid` | служебное |
| `/terms` | условия подписки (`billing.ts` `TERMS_TEXT`): что продаётся, ⭐150 за 30 дней, автопродление, отмена, возврат в течение 3 дней, `/paysupport`. Отвечает и незнакомцам |
| `/paysupport` | вопрос об оплате: текст после команды уходит админам (`ADMIN_CHAT_IDS`, пусто — первый из `ALLOWED_CHAT_IDS`) с номером записи, tg id и последней оплатой. Отвечает и незнакомцам (обязательна для бота с оплатой), но только в личке и не чаще раза в 10 минут от человека (`store.once`), иначе «вопрос уже передан» |
| `/answer <tg id> <текст>` | только владелец и админы оплаты: ответ на `/paysupport` — бот пишет человеку «💬 Ответ на ваш вопрос об оплате», запись `paysupport-answer` в `admin_log` |

| `/resume_sub` | возобновить отменённое продление (`Billing.resume` → `editUserStarSubscription(…, false)`) — та же подписка, без второй оплаты |
| `/cancel_sub` | отменить продление подписки (`Billing.cancel` → `editUserStarSubscription(…, true)`), доступ — до конца оплаченного месяца |
| `/refund <номер>` | только владелец: вернуть звёзды за последнюю оплату человека (`Billing.refund`: сперва `editUserStarSubscription(…, true)` — отменить продление, потом `refundStarPayment`), план → `free`, запись `refund` в `admin_log`; не вышло — `refund-fail` |
| `/invite` | только владелец (chat id из `ALLOWED_CHAT_IDS`): одноразовая ссылка `t.me/<бот>?start=<код>`, живёт 7 дней (`INVITE_DAYS`). С 24.11.2026 это **подарок на 30 дней** (тариф `giftDays`, `redeemInvite`): новому — запись с `plan = trial` до подарка, логин (из @username, занят — с числом; без ника — `friend`), случайный пароль, адрес сервера и ссылка на установщик (из `latest.yml`); у кого запись есть — срок +30 дней от конца нынешнего; другу (`plan = friend`) — ничего, код не тратится. О новых владельцу — не по одному, а сводкой раз в сутки после 06:00 UTC (`index.ts`, `newcomersText`: счёт и логины, без chat id) |
| `/accounts` | только владелец: сводка аккаунтов — имя, логин, с какого числа, когда последний раз писал(а) и сколько сообщений за 7 дней, расход на ИИ за месяц и всего; отдельной строкой — ничей расход и записанный до учёта по людям, внизу — всего за месяц (`accounts.ts`). Расход по людям: бот, API и фоновые задачи помечают работу для человека (`llm.ts`: `asUser`, `enterUser`), `llm_usage` хранит `user_id` (шаг 14 базы; старое — как 0); «Настройки» → «Расход» на сайте по-прежнему показывает всех вместе |
| `/model` | только владелец: какая модель отвечает — основная (`LLM_MODEL` из `.env`) или дешёвая Claude Haiku 5.5 (`anthropic/claude-haiku-5.5`, только через OpenRouter); две кнопки, выбор хранится в базе (`kv` `model:lite`) и переживает перезапуск. Дешёвая не ответила — тот же запрос сразу уходит основной. Расход пишется на модель, которая ответила (`llm.ts`: `LITE_MODEL`, `activeModel`, `setLiteModel`) |

Обычный текст, голосовые и фото (подпись к фото — подсказка, картинка файлом тоже подходит) — разбор сообщений.

## Виджет в Telegram

`server/src/widget.ts`: одно сообщение, которое бот правит на месте вместо новых. Состояние зашито в кнопки (не больше 1024 байт), запросы короткие: `d:t12` — отметить задачу 12, `u:t12` — снять отметку, `s` — обновить. Фразы вроде «покажи список» (`asksForList`) открывают его без команды.

## Игры

Трекер ПК раз в 10 минут присылает, что запущено (свой учёт программы — `desktop/src/activity.js`). Набралось за день `game_first_min` (120 мин) игры — горничная делает замечание голосом характера (`stern`), дальше — каждые `game_every_min` (120 мин). На каждый порог — одно сообщение. Выключается в настройках (`game_alerts`).

> **Пробел для развития.** Push-подписок может быть несколько (телефон, ПК, ноутбук), и каждое уведомление приходит на все — «прочитано» на одном не гасит другие.
