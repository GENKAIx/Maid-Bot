## Таблицы

Схема — `server/src/db.ts`, одна для SQLite и Postgres.

| Таблица | Что хранит |
|---|---|
| `users` | пользователь и настройки: характер, время утра/«завтра»/вечера, `event_lead_min` и `event_reminders` (когда напоминать о планах: `day`, минуты через запятую, `off`; пусто — за `event_lead_min` и в момент), игры (`game_alerts`, `game_first_min`, `game_every_min`), внешность Рины (шаг 19, «Перекрасить Рину»): `maid_hair` — волосы `red` (свои, по умолчанию) / `brown` / `gold` / `silver` / `violet` / `black`, `maid_eyes` — глаза `violet` (свои, по умолчанию) / `green` / `blue` / `amber`; id и названия — `server/src/look.ts`, те же, что `LOOK_HAIR` / `LOOK_EYES` в `desktop/renderer/look.js`; выбранные цвета подставляются в карточку Рины во всех промптах (`persona(u.persona, u)` → `rina` в `personas.ts`); «О вас» (шаг 20, `server/src/you.ts`): `address` — обращение `master` («хозяин», по умолчанию) / `mistress` («хозяйка») / `name` (по `name`), `city` — JSON выбранного города `{name, region, country, lat, lon, tz}` или пусто, `wake` — подъём в минутах от полуночи, 04:00–11:59 (с 20.11.2026; число меньше 24 — прежний час, и 7 по умолчанию у новых: читать через `wakeMinOf`), `bed` — отбой `auto` или «ЧЧ:ММ» с 18:00 до 03:59, `ask` — JSON `{set, off, last}`: какие поля человек указал сам (для «Заполнено N из 7» — у подъёма, обращения и пояса есть значения по умолчанию), о чём больше не спрашивать, когда спрашивала; `tz` меняется: город ставит свой пояс, если человек не задавал пояс сам, стёртый город уносит взятый от него пояс; пояс, выбранный самим (`ask.set` содержит `tz`), город не трогает ни при выборе, ни при стирании (`tzFollowsCity`); `weather_rain` — «Предупредить о дожде за час» (0/1, по умолчанию 0; шаг 21); платный доступ (шаг 27, `access.ts`): `plan` — `''` (не выдан) / `friend` (бесплатно навсегда: все, кто был в базе в момент шага 27, и записи из `npm run user create`) / `trial` (проба 7 дней или подарок 30) / `paid` / `free` (срок кончился), `access_until`, `tg_user_id`, `sub_charge_id`, `sub_canceled` |
| `sessions` | входы на сайт и в программу — только хеш ключа; вход, которым не пользовались 90 дней, закрывается при следующем обращении (`SESSION_IDLE_DAYS`); шаг 24 — `client` и `version`: клиент и версия из заголовков `X-Maid-Client` / `X-Maid-Version` (только белый список `web`, `desktop`, `widget`, `quick`, `iphone`, `telegram-widget` и версия вида `1.2.3`, иначе пусто — `clientMeta` в `auth.ts`); пишутся при входе и вместе с `last_seen` не чаще раза в минуту, пустой заголовок прежнее значение не затирает; `widget` и `quick` пишутся как `desktop`, а `web` у входа программы на ПК (сайт в её главном окне) клиента и версии не меняет (`sessionMeta`); индексы `sessions_user`, `sessions_seen` |
| `messages` | сырые сообщения и ответы на них; `parse_json` — разбор модели, у ответа с вопросом «Сдвинуть?» рядом с ним пара `clash: {eventId, withId}` (по ней `decideClash` узнаёт строку ⚠); у служебного сообщения поправки к ответу — её итог (`changed`, `clarify`, `asked`, `clash`, после ответа кнопкой — `clashDone`); шаг 24 — `llm_calls`: сколько логических вызовов модели ушло на сообщение (переспрос без JSON — два; повтор разбора того же сообщения прибавляет; повторы попыток и запасная модель внутри `callLlm` — один), `route` — ветка: `weather`, `chat`, `parse` (разбор упал), `clarify`, `draw`, `answer`, `apply`, `talk`, у служебного сообщения поправки — `correct` (`Pipeline.counted`; рисунок у «нарисуй» — тоже вызов; пишется без ожидания ответа); индексы `messages_at`, `messages_state` — для отчётов админки по всем людям; у упавшего сообщения (`failed`) в `reply` — код сбоя (`llmErrorCode`), у разговора — `chat:<код>`; шаг 25 стёр прежние тексты ошибок (с телом ответа провайдера) в `other` / `chat:other` |
| `diary` | записи дневника по разделам |
| `events` | планы, повторы |
| `tasks` | задачи |
| `notes` | заметки «на потом» (шаг 17): полка `shelf`, название, пометка, статус (`open`, `done`, `deleted`, `purged`), оценка `rating` 1–10 у готовой, `closed_at` |
| `dates` | важные даты: `date_iso` (год меньше года записи `created_at` — настоящий, тогда считается возраст, `yearKnown` в `report.ts`; без года — год записи), `type`, `yearly`, статус (`active`, `deleted`, `purged`), `closed_at` — когда удалена (шаг 18, для корзины) |
| `memory` | что помнить |
| `metrics` | числа: вес, сон, шаги… |
| `habits`, `habit_marks` | привычки и отметки по дням; у отметки — сколько сделано (`amount`, `unit`), если человек сам назвал число |
| `money` | деньги |
| `reminders` | запланированные и отправленные напоминания |
| `activity` | трекер ПК |
| `actions` | журнал действий для отмены: `kind` — `add` (записано), `update` / `status` / `mark` (правка словами, отметка), `edit` (правка мышью — под своим служебным сообщением; поправка к ответу — под исходным сообщением); `before_json` — прежние поля, «Отменить» идёт от новых к старым |
| `push_subs` | подписки браузеров |
| `notices` | письма горничной для виджета и сайта: текст, эмоция, кнопки, вид (`kind`, шаг схемы 15); хранится последняя тысяча на человека |
| `app_icons` | иконки программ трекера |

| `drawings` | картинки, нарисованные по просьбе: описание для модели, подпись, тип и сама картинка (base64) — ссылка RunPod живёт 7 дней |
| `traits` | дебафы и бафы профиля: вид (`debuff`/`buff`), категория, название, заметка, откуда (`user` — сами, `chat` — сказали горничной, `pattern` — она нашла), статус (`active`, `suggested` — ждёт ответа, `declined` — отказались, больше не предлагать, `removed`), дни-доказательства закономерности |
| `kv` | мелкие отметки «уже отправлено» (раз в сутки удаляются старше 60 дней — `pruneOnce`), расход токенов до таблицы `llm_usage` `llm:ГГГГ-ММ` (больше не пишется), профиль `profile:<id>` (класс — старое поле, рост, дата рождения, аватар, ссылка на профиль Steam, откуда взят аватар), попытки повтора разбора `retry:<id>`; оплата (24.11.2026): выключатель регистрации `signups:closed` (`/signups off`), отметки «вопрос об оплате уже передан» `paysupport:<tg id>:<10 мин>` и «владельцу сказано про потолок регистраций» `signupsfull:<час>` |

> **Ключи.** Пароли — scrypt, ключи входа в базе только хешем (`auth.ts`). Ключ программы на ПК лежит в её `settings.json`, зашифрованный защитой Windows (`safeStorage`), и в окна не передаётся.
| `payments` | оплаты Telegram Stars (шаг 27, `billing.ts`): ключ `charge_id` (повтор того же обновления ничего не меняет), `user_id`, `tg_user_id`, `amount` (звёзды), `currency` (XTR), `payload` (`s1:<id>:<nonce>:<подпись>`), `kind` — `first` / `renew` / `once`, `paid_at`, `expires_at`, `refunded_at` |
| `admin_log` | журнал админки (шаг 22, `admin.ts`): `at`, `user_id`, `action` — `code` / `enter` / `wrong` / `leave`, `detail`; без текстов пользователей; шаг 23 — индексы отчётов админки `actions_msg`, `actions_user`, `messages_user_at` |
| `presence` | минуты присутствия (шаг 24): `user_id` × `day_key` × `hour` (час по поясу человека) × `client` → `minutes`. Это минуты, в которые были запросы, а не время в сети (у программы на ПК — пока она запущена: виджет опрашивает сервер каждые 5 с): запись не чаще раза в минуту на человека и клиент — ограничитель в памяти в `notePresence`; у входа по сессии — вместе с `last_seen` (`authByToken`; клиент без заголовка — по метке входа, `clientFromLabel`), у `DESKTOP_TOKEN` — `desktop` (последняя версия в памяти — `desktopTokenSeen()`), у Telegram — в общем middleware бота (`telegram`). Хранится 90 дней (`pruneStats`, раз в сутки вместе с `pruneOnce`); индекс `presence_day` |
| `llm_calls` | журнал попыток модели, рисования и голоса (шаг 24): `at`, `user_id`, `kind`, `model`, `ms` — время ответа, `micro_usd`, `error_code` — пусто (удачно) или короткий код `timeout`, `net`, `http_429`, `http_5xx`, `http_4xx`, `bad_body`, `empty`, `no_key`, `other` (`llmErrorCode` в `llm.ts`); ни текста запроса, ни тела ответа провайдера. У модели и голоса — строка на каждую HTTP-попытку, у рисования — на весь заказ (цена рисования — только в `llm_usage`). Пишется без ожидания (`onLlmCall` в `index.ts`), хранится 30 дней (`pruneStats`); индекс `llm_calls_at` |
| `feature_events` | счётчики фич (шаг 26, этап 3 админки, `feature-events.ts`): `user_id` × `day_key` (по поясу человека) × `client` (`web`, `desktop`, `iphone`, `telegram`, `telegram-widget`, `push`, `other`) × `feature` (имя из белого списка `feature-list.ts`) → `count`; без текстов. Пишется пачкой из памяти раз в минуту (`addFeatureCounts`, одна транзакция, `count = count + n`); хранится 400 дней (`pruneStats`); индекс `feature_events_day` |

## Резервные копии и восстановление

| Копия | Что в ней | Где |
|---|---|---|
| Снимок базы | вся база целиком: записи, сообщения, журнал отмены, напоминания, настройки | раз в сутки после 00:00 UTC — `snapshots/maid-ГГГГ-ММ-ДД.sqlite` рядом с базой (14 последних) и `latest.sqlite` (`snapshot.ts`; только SQLite) |
| Копия на ПК | тот же снимок вне сервера | `deploy/pull-backup.ps1` забирает `latest.sqlite` по SSH в «Документы\Горничная — копии базы» (30 последних); каждый день — через Планировщик заданий Windows |
| JSON пользователя | только записи одного пользователя | раз в сутки в 03:30 в Telegram, на сайте — «Скачать копию» (`backup.ts`) |

- **Поднять базу из снимка:** скопировать файл на сервер и `bash /srv/maid/deploy/restore.sh <файл.sqlite>` — проверяет снимок (`snapshot.ts check`), останавливает горничную, прежнюю базу оставляет рядом как `maid.sqlite.before-restore-<время>`, ждёт `/healthz`.
- **Проверка руками (раз в несколько месяцев):** взять копию с ПК, на любой машине с Node 22 — `DB_FILE=<копия> npm run server` в папке проекта (без ключа бота и модели), открыть `http://localhost:3000`, войти — записи на месте.

## Секреты в логах

С 24.11.2026 всё, что сервер пишет в лог (`console.*`), и текст падения процесса проходят через `log-redact.ts` (`installLogRedaction` — первой строкой в `index.ts`): ключи из `.env` (токен бота, ключи LLM, голоса, картинок, `DATABASE_URL`, `DESKTOP_TOKEN`, закрытый ключ VAPID) заменяются на «<скрыто>», любой токен Telegram-бота вида `цифры:строка` — на «<токен бота>». Раньше grammY при сетевой ошибке печатал адрес запроса вместе с токеном. Падение по-прежнему завершает процесс с кодом 1 (Docker поднимает его заново). Проверка — `server/test/log-redact.test.ts`.

## Адреса

Все `/api/...` — с ключом `Bearer`, кроме входа и публичных.

| Группа | Адреса |
|---|---|
| Админка | только админу (`isAdmin`, иначе 404); с 24.11.2026 — `GET /api/admin/payments` (оплаты: имя, звёзды, вид, когда, до какого, возврат; от `charge_id` — только хвост, без payload и chat id), `POST /api/admin/refund {user_id}` (возврат последней оплаты, запись `refund` в журнал), в `overview` — `billing: {stars_30, subscribers, trials, expired, friends}`; `GET /api/admin/state` (`until` — до когда вход подтверждён, `telegram`), `POST /api/admin/code` (код в Telegram; 429 — рано, 503 — бота нет), `POST /api/admin/confirm` (`{code}`), дальше — только с подтверждённым входом (иначе 403): `/api/admin/overview`, `/api/admin/users`, `/api/admin/spend?days=`, `/api/admin/audience`, `/api/admin/quality?days=`, `/api/admin/health` (этап 2), `/api/admin/log`, `POST /api/admin/leave` (`admin-stats.ts`; только счётчики и имена); `GET /api/admin/features` — использование функций (этап 3) |
| Счётчики функций | `POST /api/events/usage` (любой вошедший): `{ client?, counts: { имя: сколько } }`; клиент — по заголовку `X-Maid-Client` (виджет и быстрая запись — `desktop`; нет заголовка — из тела по тому же списку; бот, push и виджет Telegram пачки не шлют — их считает сервер). Берутся только имена, которые считает клиент (`by: "client"` в `feature-list.ts`), остальные отбрасываются молча (`dropped`); счёт — 1…500, больше — срезается; имён больше 100 — 400; чаще раза в минуту на человека и клиента — 429 «счётчики — не чаще раза в минуту» (клиент оставляет счёт себе); за день одной фичи из пачек у человека берётся не больше 2000 по всем клиентам вместе (`USAGE_DAY_MAX`, сверх — срезается молча: скрипт с ключом не раздует отчёт). Сам запрос не отмечает ни `last_seen`, ни минуту присутствия (`authByToken` с `quiet`): пачка уходит и из фоновой вкладки. Ответ `{ ok, accepted, dropped }`. В базу — не сразу, а пачкой раз в минуту. Сервер сам считает только удавшееся: ручку — по ответу 200 (повтор того же сообщения — `/api/input`, `/api/voice` с прежним id, ответ `duplicate` — не в счёт), ветку разбора — если модель ответила (упавшие разговор, ответ, рисунок — не в счёт), голосовое в Telegram — после распознавания, кнопку push — после того, как она сработала; «Повторить» на сайте, в программе и в Telegram записанное считает (клиент — кто нажал), фоновый повтор — нет. Остановка сервера ждёт идущие запросы не дольше 3 с и пишет пачку |
| Служебные | `/healthz`, `/webhook` (Telegram; с 24.11.2026 — только с заголовком `X-Telegram-Bot-Api-Secret-Token`, иначе 401: секрет выводится из токена бота, `webhook.ts`, и передаётся Telegram в `setWebhook` при запуске) |
| Вход | `/api/login`, `/api/logout`, `/api/me` (строка `users` без `password_hash`, в т. ч. `maid_hair`, `maid_eyes`, и `sessions`; с 24.11.2026 — `access: {plan, until, canceled, trial_left_days}`, `plan` — `owner` / `friend` / `trial` / `paid` / `expired`), `/api/public` |
| Подписка | `POST /api/billing/link` → `{url}` — ссылка на оплату в Telegram (сутки из kv `paylink:<id>`; платить не нужно — владелец, друг, подписка и так идёт — 409 с причиной; бота нет или Telegram не ответил — 503 «попробуйте чуть позже»), `POST /api/billing/cancel` — отменить продление, `POST /api/billing/resume` — возобновить (нет подписки — 409). Работают и без доступа к ИИ. **ИИ закрыт** (`access.ts`): `/api/input`, `/api/voice` (до распознавания), `/api/correct`, `/api/messages/:id/retry` отвечают **402** `{error, pay_url, messageId, saved}` — нет пробы или подписки (текст уже записан заметкой; `saved: false` — ничего не записано, у голоса), **429** — дневной потолок (свой или общий у проб) и частота у голоса. Частота у текста — не отказ: ответ «не удалось» (`failed`), сообщение разберёт фоновый повтор. Не 401: на 401 сайт и программа стирают ключ |
| Настройки | `/api/settings` (характер — только из `PERSONAS`, иначе 400; `maid_hair`, `maid_eyes` — только id из `look.ts`, иначе 400 «нет такого цвета»; ответ — строка `users` без `password_hash`), `/api/personas`, `/api/backup` |
| Push | `/api/push/key`, `/api/push/subscribe`, `/api/push/unsubscribe`, `/api/push/test`, `/api/push/act` |
| День | `/api/today` (день целиком и рядом `persona`, `maid_hair`, `maid_eyes` — по ним виджет ПК перекрашивает анимации на каждом опросе; `upcoming`, `far_fresh`, `gone_fresh`, `done_fresh`, `tasks`, `notes`, `done_today`, `dates`, `xp` — опыт и уровень `{ xp, level, into, need }` для полосы в шапке виджета ПК, та же формула, что в профиле, `profile.ts xpOf`; `call` — слово обращения («хозяин», «хозяйка» или имя), `wake_at` — подъём «06:30», `wake` — его час (для виджетов до 0.1.83), `bed` — отбой из «О вас»; `ask` — вопрос Рины о вас для облачка `{field, text, buttons}` или null (`askNext`); `you_set` — какие из подъёма и отбоя человек выбрал сам (виджет не переносит поверх них прежние настройки ПК); `todayJson`), `/api/day`, `/api/notices` |

| Задачи и даты | `/api/tasks`, `POST /api/tasks/:id` (`status`, в т. ч. `deleted`; `due_date`; `title`), `POST /api/tasks/:id/plan` (задача → план), `POST /api/tasks/:id/copy` (`date`), `GET /api/dates` (`?all=1` — на год вперёд; у каждой `on`, `inDays`, `age`, `year_known`), `POST /api/dates` (`title`, `month`, `day`, `year` или null, `type`, `yearly`; отменяется — `undo`), `POST /api/dates/:id` (то же по частям, `status`: `deleted` — в корзину, `active` — вернуть); корзина — `dates` в `GET /api/trash` и `POST /api/trash/purge` (проверка — `server/test/dates-edit.test.ts`) |
