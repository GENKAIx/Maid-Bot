# Как писать фрагмент макета для ревью «Горничной»

Ты пишешь ОДИН файл-фрагмент: `parts/<ключ>.html` в этой папке (`scratchpad/review3`). Главная сессия потом склеит все фрагменты в одну страницу вместе с `shared.css` и `shared.js`. Прочитай оба этих файла ЦЕЛИКОМ до начала: в них токены цветов, готовые рамки и классы.

## Читатель
Владелец продукта, не программист. Пиши по-русски, простыми словами, короткими предложениями. Никаких терминов без объяснения. Данные в макетах — выдуманные, но правдоподобные (обычный человек: работа за ПК, сон 6–8 ч, привычки «Чтение», «Вода», «Зарядка», траты на еду и транспорт). Не используй реальные личные данные.

## Форма фрагмента (строго)
```html
<article class="piece" id="p-КЛЮЧ">
  <header>
    <p class="eyebrow">Экран · Обзор</p>
    <h2>Короткое название идеи</h2>
    <p>2–3 предложения: что это и какую боль снимает.</p>
  </header>
  <button class="replay" type="button">Повторить анимацию</button>

  <div class="app" data-hub="stats" data-tab="Сон" data-title="Сон">
    … содержимое экрана (рамку окна, меню и вкладки достроит shared.js) …
  </div>

  <div class="notes">
    <div><h4>Что изменилось</h4><ul><li>…</li></ul></div>
    <div><h4>Анимации</h4><ul><li>что движется, когда и зачем</li></ul></div>
    <div><h4>Что нужно в коде</h4><ul><li>честно: какие данные уже есть, что надо дописать</li></ul></div>
  </div>

  <style> /* ВСЕ селекторы начинаются с #p-КЛЮЧ */ </style>
  <script>(function () { "use strict"; var root = document.getElementById("p-КЛЮЧ"); … })();</script>
</article>
```
- `data-hub`: today | plans | diary | stats | rina | gear (gear = Настройки). `data-tab` — одна из вкладок узла (список в shared.js, TABS). `data-title` — заголовок экрана.
- Если нужно несколько вариантов экрана — сделай переключатель «Вариант А / Вариант Б» (`.seg` с `aria-pressed`) НАД рамкой и две рамки `.app`, из которых видна одна (`hidden`). Под переключателем одна строка: какой вариант советуешь и почему.
- Для макетов НЕ полной версии (виджет, Telegram, телефон, окно входа, админка) бери готовые рамки из shared.css: `.wgt`, `.tg`, `.phone`, `.app.plain`, `.adm[data-section][data-group]`, и раскладку `.scene > figure > figcaption`.

## Жёсткие правила
1. **Цвета только токенами.** Внутри `.app` — `var(--a-*)` и `var(--c-*)`; внутри `.adm` — `var(--d-*)`, `var(--s1..s6)`; внутри `.wgt` — `var(--w-*)`; внутри `.tg` — `var(--t-*)`; на странице вне рамок — `var(--bg|card|line|text|soft|muted|accent|ok|warn|bad|gold)`. Никаких `#hex` и `rgb()` в своём CSS/SVG (кроме `transparent`, `currentColor`, `color-mix(in srgb, var(--токен) N%, transparent)`). Экран обязан читаться в обеих кожах (тёмной и светлой) — кожу переключает страница.
2. **Цвет данных закреплён за сущностью:** сон `--c-sleep`, компьютер `--c-pc`, игры `--c-game`, привычки `--c-habit`, деньги `--c-money`, настроение/оценка `--c-mood`. «Хорошо/внимание/плохо» — `--a-ok/--a-warn/--a-bad`, только вместе со значком или словом.
3. **Только свой корень.** CSS — все селекторы с `#p-КЛЮЧ`. JS — в IIFE, без глобальных переменных, ищи элементы через `root.querySelector`. Свои `id` внутри — с префиксом `КЛЮЧ-`. Без библиотек, без внешних картинок и шрифтов. `@keyframes` называй с префиксом `КЛЮЧ-`.
4. **Рина.** Картинки (анимированные webp 180×192): `maid/<имя>.webp`. Есть: analysis, angry, bedtime, bow, done, excited, giggle, happy, hello, idle, letter, list, listen, neutral, pout, present, proud, sad, salute, shy, sleep, smug, streak, surprised, tea, think, thumbsup, worried, write. На каждом экране полной версии — один блок `.rina` с её наблюдением по данным экрана (её голос: заботливая, на «вы», коротко, без канцелярита).
5. **Анимации.** Страница должна быть полной и читаемой БЕЗ анимаций (ничего не оставляй в `opacity: 0` навсегда). Анимации запускай так: `MaidMock.onSeen(root, play)` и `root.addEventListener("replay", play)`; `play()` обязан уметь перезапускаться. Если `MaidMock.reduce` — сразу конечное состояние. Анимируй смысл: рост столбиков, прорисовку линии, перелёт карточки, счётчик, отклик на действие. Длительности 200–900 мс, `var(--ease)`. Без бесконечного мелькания (максимум одно спокойное «дыхание»).
6. **Живое.** Основные действия должны работать прямо в макете (клик, перетаскивание, переключатель, ввод) и давать отклик — это макет поведения, а не картинка. Состояние — только в памяти (без localStorage).
7. **Телефон.** Ширина 375 px: ничего не вылезает по горизонтали. Сетки через `minmax(0, 1fr)`, у текстовых детей `min-width: 0`, широкие графики — в своём контейнере с `overflow-x: auto` или перестраиваются. SVG — с `viewBox` и `width: 100%`. Цели для пальца ≥ 36 px.
8. **Доступность.** Кнопки — `<button type="button">`, у значков `aria-label`, переключатели с `aria-pressed`, видимый фокус не убирать. Подсказки не только по наведению.
9. **Графики.** Одна ось (никаких двух шкал Y). Текст на графиках — токены текста, не цвет серии. Подписи значений выборочно, не на каждой точке. У графика есть наведение/касание с подсказкой (значение + дата).
10. **Размер.** Файл до 80 КБ. Без комментариев-простыней.
11. **Тексты.** Без «не X, а Y», без тире-вставок, без англицизмов и жаргона. В текстах интерфейса — как в настоящем продукте.

## Проверка перед сдачей
Запусти: `python check.py parts/<ключ>.html` (из папки review3) — он проверит синтаксис скрипта, запретные цвета, префиксы. Исправь всё, что он назовёт ошибкой. Браузерные инструменты НЕ используй (ими пользуется главная сессия). Файлы проекта «Горничная бот» не меняй; `shared.css`, `shared.js`, `SPEC.md`, `check.py` не меняй. Пиши только свой файл в `parts/`.

## Что вернуть
Одной-двумя фразами: что нарисовано, какие варианты, что check.py прошёл. Без пересказа кода.
