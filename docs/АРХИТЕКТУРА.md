| Mini App | статистика (сон, шаги, ПК, игры), задачи, даты, планы | |

Удачные правила, которые переносим как есть:
- обычный текст = запись, без подтверждения; `/ask` — просто поговорить;
- сон: не выдумывать время подъёма; сны — в конец «Сна»;
- еда: «купил» ≠ «съел» — покупки в заметки;
- игры в дневник пишет только трекер ПК, не текст пользователя;
- «Саммари» — почти дословная выжимка сообщения, с `[ЧЧ:ММ]`, без «записано…»;
- не распознал разделы — пишем только в саммари, ничего не раскидываем наугад;
- короткое подтверждение после записи, полный отчёт — вечером;
- игровые уведомления — один раз на каждый новый полный час;
- доступ только своему chat id; Mini App проверяет `initData`.

## 2. Что меняем (решения пользователя 08.11.2026)

1. **Своя база.** SQLite у себя (`node:sqlite`) или Postgres на Render (`DATABASE_URL`) — один код:
   `driver.ts` переводит `?` и типы ключей под базу, все запросы асинхронные. Google Таблицы нет
   (решение пользователя 08.11.2026), старая Excel-таблица перенесена скриптом `import.ts`.
2. **Свободный ввод без режимов.** Один вызов LLM разбирает всё сообщение сразу: дневник по разделам,
   планы, задачи, важные даты, факты памяти, правки (отменить/выполнить/перенести), вопрос.
   Модель видит ближайшие планы и открытые задачи с номерами — и правит их по номеру.
   Неясно (07:00 или 19:00?) — один короткий вопрос, черновик ждёт ответа в базе.
3. **Каждое действие отменяемо.** Кнопки «↩ Отменить» и «📝 Это просто заметка» под ответом.
4. **Напоминания живут в базе**, переживают перезапуск: утром — план дня, вечером — план на завтра,
   за час до встречи, даты за 7 дней / за день / в день, вечерний итог в выбранном характере.
   Никаких внешних планировщиков.
5. **Характеры горничной**: строгая-заботливая (как раньше), добрая, дерзкая, расслабленная.
   Эмоция к каждому ответу (`emotion`), картинки — набор `assets/emotions/<характер>/<эмоция>.png`
   (пока не нарисованы — бот шлёт только текст).
6. **Десктоп (Electron)**: окно (сегодня, планы, задачи, даты, ввод), **виджет поверх всех экранов**
   (прозрачный, сквозь него можно кликать, Alt+Shift+M — взять/отпустить), быстрый ввод по
   Alt+Shift+Space, трей; трекер ПК — читает ActivityWatch каждые 10 мин, AFK вычитается, шлёт на сервер.
7. **Один код на нескольких пользователей** (таблица `users`), но доступ пока по списку chat id.

## 3. Устройство

```
server/   TypeScript (tsx), без сборки
  config.ts     .env → настройки
  time.ts       даты в часовом поясе пользователя
  driver.ts     SQLite / Postgres под одним интерфейсом
  db.ts         схема (миграции) и запросы
  auth.ts       пароли (scrypt), ключи входа (в базе — хеш)
  habits.ts     привычки: расписание, серии, сетка месяца
  llm.ts        OpenAI-совместимый API (OpenAI / OpenRouter), JSON-ответ
  parse.ts      промпт и схема разбора (zod), проверка дат/времени
  pipeline.ts   сообщение → запись → разбор → действия → ответ (повтор доставки не дублирует)
  personas.ts   характеры и их фразы
  report.ts     тексты: день, планы, задачи, даты, активность
  scheduler.ts  напоминания и итоги
  api.ts        HTTP: webhook Telegram, API приложений (вход, сегодня, привычки, деньги, показатели, шаги, поиск, push, настройки, копия)
  push.ts       Web Push: подписки, подпись кнопок (HMAC), «отложить»
  backup.ts     резервная копия JSON (в Telegram ночью, скачать из приложения, npm run backup)
  import.ts     перенос Excel «2026 заметки» (повторный запуск безопасен)
  user.ts       учётные записи из командной строки
  bot.ts        Telegram (grammY)
  widget.ts     виджет Telegram (Bot API 10.4) «Список на сегодня» — /list: HTML с галочками в сообщении, состояние до 1024 байт
                пишет бот (editMessageWidgetData), нажатия приходят как widget_query («d:t12» сделано, «u:t12» вернуть, «s» обновить)
                «что на сегодня?», «что осталось», «мои дела» — тоже виджет; последний присланный живой: после любой записи/отметки
                бот обновляет его (Pipeline.onChange → kv widget:<id>)
                в шапке — личико горничной (webp 44 px внутри HTML, лимит виджета 4 КБ сжатого): галочка — прыжок, всё — пляска, пусто — спит;
                всё на сегодня сделано — видеостикер server/assets/maid/done.webm (из анимации маскота, ≤256 КБ) раз в день (kv cheer:<id>)
  index.ts      запуск
web/      React + Vite + TypeScript — веб-приложение (PWA), сборка в web/dist, её отдаёт сервер с корня
  src/App.tsx         каркас: вход, навигация (слева на ПК, снизу на телефоне), строка ввода
  src/screens/        Today, Diary (календарь, день), Habits (сетка месяца), Plans (неделя, задачи, даты), Health (подразделы, поиск),
                      Money (период, категории), Stats (ПК, игры, сон, шаги, спорт по дням/неделям/месяцам)
  src/charts.tsx      столбики, доли, переключатель периода — без библиотек
  src/api.ts          запросы, ключ входа в localStorage; 401 — снова экран входа
  src/push.ts         регистрация service worker, подписка на push
  public/sw.js        service worker: уведомление с кнопками, кнопка → /api/push/act без входа
render.yaml  Render: сервер + Postgres (docs/RENDER.md)
  src/format.ts       даты, разделы, длительности (как у бота)
desktop/  Electron (JS)
  main.js       окна, трей, горячие клавиши, трекер; главное окно — веб-приложение с сервера; окно горничной (hover-мышь)
  assets/maid/  фигурка: 20 анимаций <состояние>.webp (из «А ПРИКОЛЫ/Маскот/Анимации», общая рамка)
  activity.js   ActivityWatch → активность дня
  renderer/     index.html (настройки и запасной вид), widget.html (горничная + панель + облачко), quick.html (быстрая запись)
  renderer/tails.js  хвосты: просроченная открытая задача — вопрос в облачке («Сделано» / «Не сделано» = failed / день недели = перенос, POST /api/tasks/:id)
```

Поток сообщения: `messages` (received) → разбор → действия в своих таблицах, каждое пишется в `actions`
(для отмены) → `state = done` → ответ. Упало посередине — сообщение остаётся `received`,
повторная доставка Telegram его дообрабатывает, а не создаёт копию.
